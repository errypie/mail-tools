# GigaMail

Почта и календарь Exchange с ИИ-инструментами GigaCode CLI. Репозиторий: `mail-tools`.

Сервис забирает письма из Exchange, складывает их в локальную базу и просит модель определить категорию, написать
короткое саммари и решить, нужно ли действие. В веб-интерфейсе вы видите письма с разбором, а агент запускается
только по вашей кнопке. Ход его работы можно смотреть вживую: мысли, инструменты, запросы разрешений.

> Проверено на тестовых письмах и тестовом агенте из `tests/`, а работа с Exchange — на имитации почтового ящика.
> С настоящими сервером Exchange и CLI `gigacode` проект ещё не запускался. На Windows тоже не проверялся.
> Что смотреть при первом запуске, описано в разделе [Первый запуск на рабочей машине](#первый-запуск-на-рабочей-машине).

## Из чего состоит

Это только почта. Агента запускает отдельный сервис из репозитория [gigacode](https://github.com/errypie/gigacode),
поэтому нужны две папки и два процесса на одной машине:

```text
Exchange (EWS) ──> mail-tools :8770 ──> gigacode :8765 ──> gigacode --acp
                   письма, база,        живые сессии агента,
                   веб-интерфейс        веб-чат и HTTP API
```

| Папка | Что внутри |
|---|---|
| `mail-tools/mailbot/` | Опрос Exchange, база писем, категории, шифрование секретов, веб-интерфейс |
| `mail-tools/tests/` | Тестовый агент для проверки почты без настоящего CLI |
| `gigacode/` | Отдельный репозиторий: запускает `gigacode --acp`, отдаёт чат и HTTP API |

## Что нужно

- Python 3.9 или новее.
- Репозиторий [gigacode](https://github.com/errypie/gigacode) рядом с этим.
- CLI `gigacode`, который запускается из терминала и уже авторизован. Проверка: `gigacode --help`.
- Доступ к серверу Exchange по EWS, обычно через VPN или рабочую сеть.
- Адрес сервера Exchange, адрес ящика, логин и пароль.
- Корневой сертификат компании, если сервер использует внутренний удостоверяющий центр.

Сервису gigacode внешние библиотеки не нужны. Почте нужны `exchangelib` и `cryptography`.

## Установка одной командой на Linux

Скрипт `install.sh` ставит оба репозитория, зависимости и сервисы `systemd --user`. Права root не нужны, `sudo` не используйте.
Сервисы запускаются при входе в систему и перезапускаются после сбоя.

Скачайте скрипт из репозитория и запустите его, указав адрес группы:

```bash
./install.sh --git-base https://git.example.com/team
```

Всё ставится в `/home/work/<пользователь>`, если такой каталог есть, иначе в `~/gigacode-mail`. Другой каталог задаётся через
`--root`. Если запустить скрипт из клона `mail-tools`, `gigacode` появится рядом, а адрес возьмётся из `origin`.

| Каталог | Что там |
|---|---|
| `gigacode/`, `mail-tools/` | Код. Окружение Python лежит в `mail-tools/.venv` |
| `mail-tools/mail_data/` | Письма, настройки, зашифрованные секреты |
| `workspace/` | Рабочий каталог агента, меняется через `--workdir` |
| `config/` | Переменные окружения сервисов. Свои значения пишите в `config/local.env` |

Файлы сервисов лежат в `~/.config/systemd/user`: в другом месте `systemd --user` их не увидит.

Логин и пароль git спрашиваются один раз на оба репозитория. Пароль хранится только в памяти до конца установки, в файлы не попадает.

`PATH`, настройки прокси и пути к сертификатам скрипт берёт из вашего терминала. Запускайте его там, где уже работает `gigacode`.

| Параметр | Зачем |
|---|---|
| `--gigacode-cmd "node /путь/к/cli.js"` | `gigacode` нет в `PATH` |
| `--pip-index URL` | Внутреннее зеркало пакетов |
| `--update` | Обновить код и зависимости, затем перезапустить сервисы |
| `--uninstall` | Удалить сервисы. Код и данные останутся |

После каждого перезапуска сервиса войдите в веб-интерфейс: ключ шифрования живёт только в памяти, без него почта не опрашивается.

```bash
systemctl --user status mailbot gigacode-serve
```
```bash
journalctl --user -u mailbot -f
```

Если сервисы должны работать и без входа в систему, включите `loginctl enable-linger`. На рабочей машине это может быть запрещено.

## Запуск

Нужны два терминала.

**Терминал 1, сервис GigaCode.** Запускайте из папки `gigacode`. В `--workdir` укажите каталог, где агент будет работать по умолчанию:

```bash
python3 server.py --workdir /путь/к/рабочему/каталогу
```

Если `gigacode` нет в `PATH`, передайте команду явно:

```bash
python3 server.py --workdir /путь/к/каталогу --cmd "node /полный/путь/к/gigacode/dist/cli.js"
```

Откройте http://127.0.0.1:8765. Если чат отвечает, агент работает.

**Терминал 2, почта.** Запускайте из папки `mail-tools` с активным окружением `.venv`:

```bash
python3 -m mailbot
```

Откройте http://127.0.0.1:8770.

## Первая настройка

### 1. Пароль входа

При первом открытии задайте пароль, минимум 8 символов. Им шифруются логин и пароль Exchange.
**Забытый пароль не восстановить.** Что делать в этом случае, описано в разделе [Секреты и данные](#секреты-и-данные).

### 2. Exchange

Откройте «Настройки» → «Exchange»:

| Поле | Что указать |
|---|---|
| Сервер | Только имя, без `https://`: `mail.example.com` |
| Адрес ящика | `name@example.com` |
| Логин | Обычно `DOMAIN\user`. Если вход не проходит, попробуйте `user@example.com` |
| Пароль | Пароль учётной записи |
| Авторизация | `NTLM` для большинства внутренних серверов, иначе `BASIC` |
| Корневой сертификат | Полный путь к файлу `.pem` или `.crt`, если сервер использует внутренний сертификат |
| Интервал опроса | Как часто проверять почту, по умолчанию 15 секунд |
| При первом запуске брать за, дней | Насколько старые письма забрать при первом запуске, по умолчанию 3 |

Нажмите «Сохранить и проверить подключение». Адрес автообнаружения не используется: сервис идёт прямо на
`https://<сервер>/EWS/Exchange.asmx`.

### 3. GigaCode

«Настройки» → «GigaCode»:

| Поле | Что указать |
|---|---|
| Адрес сервиса | `http://127.0.0.1:8765` |
| Токен | Только если сервис запущен с `--token` |
| Рабочий каталог скиллов | Каталог по умолчанию для запуска по кнопке. Пусто — каталог из `--workdir` |
| Разрешения при запуске скилла | Что делать с запросами агента. Сначала лучше выбрать «спрашивать в чате GigaCode», см. раздел [Безопасность](#безопасность) |
| Сколько символов письма отправлять | Ограничение длины письма для модели, по умолчанию 12000 |

### 4. Проверка

Индикаторы Outlook и GigaCode в шапке должны стать зелёными. Клик по индикатору открывает страницу статуса.
На ней кнопка «Проверить запуск агента» поднимает настоящий процесс `gigacode --acp` и закрывает его.

## Категории и промпты

Кнопка «Категории» в шапке открывает отдельную страницу. Сразу есть категории `RELEASE`, `SPAM`, `AUTO`, `UNINFO`
и `UNKNOWN`. Их можно менять, удалять и добавлять свои. У категории есть код (латиница, цифры, `_` и `-`) и название.

### Когда выбирать

Промпт для разбора письма. Модель читает его при разборе каждого письма вместе с промптами других категорий.
На этом шаге она не запускает инструменты и не открывает файлы, поэтому здесь нужны только признаки письма:

```markdown
## Признаки
Письмо про релиз или приёмку задачи.

- В теме или тексте есть Jira-ключ вида ABC-123
- Отправитель из команды релизов

Не путать с автоматическими уведомлениями Jira: их относи к AUTO.
```

Чем длиннее описания всех категорий, тем больше каждый запрос и медленнее разбор.

### Промпт запуска

Текст, который уйдёт агенту по кнопке в письме. Если он пуст, кнопки действия не будет. Здесь пишите скиллы, пути,
код и команды. Перед запуском текст можно поправить прямо в письме.

```markdown
Запусти скилл release-check для задачи {jira_key}.

Сверь изменения с чек-листом и сохрани отчёт в `/data/reports/{jira_key}.md`.

Контекст:
- Тема: {subject}
- Саммари: {summary}

Файлы:
{files}
```

Подставляются переменные:

| Переменная | Значение |
|---|---|
| `{jira_key}` | Jira-ключ из письма |
| `{subject}` | Тема |
| `{sender}` | Адрес отправителя |
| `{summary}` | Саммари модели |
| `{action_hint}` | Совет модели |
| `{body}` | Полный текст письма |
| `{files}` | Список файлов из окружения категории |
| `{ваш_код}` | Значение вашей сущности, см. раздел [Свои сущности](#свои-сущности) |

Неизвестная переменная подчёркивается красным и уходит агенту как есть.

Те же переменные работают в поле «Запустить агента» в письме, даже если у категории нет промпта запуска. Под полем есть
кнопки с переменными, а в блоке «Что уйдёт агенту» видно итоговый текст с настоящими значениями.

### Свои сущности

Сущность — это значение, которое модель достаёт из письма, как `{jira_key}`. Например, номер договора или название стенда.
Создаётся в «Настройки» → «Сущности»:

| Поле | Что указать |
|---|---|
| Код | Имя переменной: латиница, цифры и `_`, начинается с буквы. Код `contract_id` даст `{contract_id}` |
| Название | Как показывать значение в письме |
| Что искать в письме | Описание для модели |
| Регулярное выражение | Необязательно. Проверяет ответ модели. Если ответ не подошёл, значение ищется прямо в теме и тексте письма. Если в выражении есть группа, берётся первая |

Сущность появится кнопкой в письме и в редакторе промптов. Значения находятся при разборе, поэтому они есть у новых писем.
Для старых нажмите «Переразобрать письма» на странице категорий. Пустое значение заменяется пустой строкой.
Описания всех сущностей уходят модели с каждым письмом.

### Окружение GigaCode

Действует только при запуске по кнопке. Пустое поле берёт значение из настроек или сервиса GigaCode.

| Поле | Что делает |
|---|---|
| Рабочий каталог | Где запускается агент |
| Файлы для агента | Список путей, по одному на строку. Попадает на место `{files}`, а без этой переменной дописывается в конец |
| Дополнительные каталоги | Передаются в `--include-directories`, по одному на строку |
| Режим подтверждений | `plan`, `default` или `auto-edit` |
| Разрешения инструментов | Разрешать всё, спрашивать или отклонять |
| Модель | Идентификатор модели для этой категории |

Каталоги должны существовать на машине, где работает сервис GigaCode. Иначе запуск завершится ошибкой, и она будет видна в письме.

### Проверка на письме

Вкладка показывает оба итоговых промпта и прогоняет разбор на выбранном письме. Берётся текущий текст, даже
несохранённый, а само письмо не меняется.

### Редактор

Markdown с подсветкой кода, путей и переменных, нумерация строк, просмотр рядом, вставка кода и путей.
Клавиши: Ctrl+S сохраняет, Ctrl+B делает текст жирным, Tab и Shift+Tab меняют отступ, Enter продолжает список.

Изменения действуют на новые письма. Чтобы применить их к старым, нажмите «Переразобрать письма»: это один запрос
к модели на письмо. При смене кода категории письма переезжают вместе с ней. Письма удалённой категории остаются
слева с пометкой «удалена».

### Исправить категорию письма

Если модель ошиблась, выберите другую категорию в списке под темой письма. Письмо сразу переедет, у него появится метка
«выбрано вручную» и промпт запуска новой категории. Модель при этом ничего не делает.

«Переразобрать письма» такую категорию не меняет, обновляются только саммари и сущности. Чтобы снова отдать решение
модели, нажмите в письме «Классифицировать заново».

## Белый и чёрный списки

«Настройки» → «Отправители», по одному адресу или домену на строку: `name@example.com`, `@example.com`.

- Если белый список заполнен, берутся только письма из него. Если пуст, берутся все.
- Чёрный список важнее белого.
- Отсеянные письма не сохраняются и не уходят в модель.
- Кнопки «В чёрный список» и «Заблокировать домен» есть в самом письме.
- Списки действуют на новые письма. Письмо, отсеянное раньше, вернётся после снятия блокировки, только если оно попало в последние 5 минут опроса.

## Работа с письмами

1. Сервис забирает новые письма из Inbox. Признак «прочитано» не используется и не меняется, дубли отсекаются по `Message-ID`.
2. Один запрос к модели возвращает категорию, уверенность, саммари, Jira-ключ и рекомендацию.
3. При сбое или ответе не в JSON будет 5 попыток с растущей паузой, затем статус «Ошибка» и кнопка «Классифицировать заново».
4. Если GigaCode недоступен, попытки не тратятся: письма ждут в очереди и разбираются после восстановления.
5. Кнопка в письме создаёт живую сессию. Ссылка «Открыть в GigaCode» показывает мысли и инструменты агента.

Интерфейс:

- Границы между папками, списком и письмом тянутся мышью. Двойной клик по границе сбрасывает ширину.
- Кнопка «↗ В отдельном окне» открывает письмо без списка: текст слева, разбор и запуск агента справа.
- Страница статуса показывает последний опрос, очередь, текст ошибок и подсказки, что проверить.

## Чтение писем

Письма показываются как в Outlook: со стилями, таблицами и встроенными картинками. Текст письма отрисовывается
в изолированной рамке, где скрипты не выполняются, а опасные ссылки и формы вырезаются.

Картинки из интернета по умолчанию скрыты: по ним отправитель узнаёт, что письмо открыли. Кнопка «Показать картинки»
загружает их для этого письма.

Вложения видны под заголовком письма. Картинки, PDF и текстовые файлы открываются в просмотре, остальное скачивается.
Содержимое вложений не хранится в базе: сервис берёт его из Exchange при открытии и держит в памяти до 64 МБ.
Письма, полученные до этой версии, показываются текстом и без вложений.

## Папки и работа с ящиком

Слева показаны все почтовые папки ящика Exchange, включая вложенные, с числом непрочитанных. Календарь, контакты
и задачи в этот список не попадают. Вложенные папки сворачиваются стрелкой.

- **Непрочитанные** выделены жирным и синей полосой. Письмо отмечается прочитанным, когда вы его открываете.
  Отметить его обратно можно кнопкой с конвертом у письма или в списке. Отметки уходят в Exchange, а прочитанное
  в Outlook GigaMail подхватывает при следующем опросе: изменения во «Входящих» он забирает через `SyncFolderItems`.
- **Удаление**: кнопка с корзиной или клавиша Delete. Письмо уходит в «Удалённые», как в Outlook. Из «Удалённых»
  письмо удаляется навсегда, после подтверждения.
- **Перемещение**: кнопка «Переместить в папку» с поиском по папкам или перетаскивание письма из списка на папку слева.
- **Другие папки** GigaMail читает с сервера при открытии, по 50 писем. Кнопка «Загрузить более старые письма»
  внизу списка подгружает следующую порцию, во «Входящих» тоже. Письма, которые удалили или переместили в Outlook,
  из списка пропадают.
- **Поиск**: при вводе в строку поиска список фильтруется по уже загруженным письмам. Enter ищет во всех папках на
  сервере, как поиск Outlook. Рядом с каждым найденным письмом подписана его папка. Сброс — кнопкой «Сбросить» или Esc.
- **Цепочки.** Под письмом показана вся переписка из всех папок, включая ваши ответы из «Отправленных».
  Каждое письмо цепочки разворачивается на месте. Переключатель «Цепочки» над списком собирает письма одной
  переписки в одну строку с числом писем.
- Модель разбирает только новые письма во «Входящих». Письма из других папок, старые письма и результаты поиска
  она не трогает, а разобрать такое письмо можно кнопкой «Классифицировать заново».
- В категориях GigaCode видны письма из всех папок, кроме «Удалённых».
- «Черновики» в меню — это черновики GigaMail. Черновики, начатые в Outlook, открываются только в Outlook.

## Написание писем

«Новое письмо» в меню слева. «Ответить», «Ответить всем» и «Переслать» есть под заголовком открытого письма.

- **Адресаты.** Начните вводить имя или адрес, и появятся подсказки. Сначала идут люди из вашей переписки, чаще всего
  первыми те, кому вы писали сами. От трёх символов к ним добавляется адресная книга Exchange. Адрес можно вписать
  и вручную, а неверный подсвечивается красным. Поля «Копия» и «СК» (скрытая копия) открываются ссылками справа.
- **Ответ всем** подставляет отправителя и всех адресатов исходного письма, кроме вас. Тема получает `RE:`,
  пересылка получает `FW:`, без повторов вида `RE: RE:`.
- **Исходное письмо** цитирует под вашим текстом сам Exchange, как в Outlook. При пересылке он же прикладывает
  вложения исходного письма, они показаны в черновике с пометкой «из исходного письма».
- **Вложения**: кнопка «Вложить файл» или перетаскивание файлов в окно письма. Всего до 25 МБ на письмо. До отправки
  файлы лежат в `mail_data/uploads/` и доступны только вашему пользователю ОС. После отправки или удаления черновика
  они стираются.
- **Черновики** сохраняются сами через секунду после правки, а также при закрытии окна и уходе к другому письму.
  Они собраны в разделе «Черновики» и хранятся в базе GigaMail, а не в папке «Черновики» Outlook. Пустой черновик
  удаляется при закрытии.
- **Отправка** по кнопке или Ctrl+Enter. Копия сохраняется в «Отправленных» Exchange. В разделе «Отправленные»
  GigaMail видны только письма, отправленные из GigaMail. Если отправить не удалось, черновик остаётся с ошибкой,
  и его можно поправить и отправить снова.
- **Оформление**: жирный, курсив, подчёркнутый, списки, цитата и ссылки. Скопированный текст вставляется без
  оформления, чтобы в письмо не попал чужой HTML.

### Черновик от GigaCode

Кнопка «Ответ от GigaCode» у письма открывает ответ, и модель сразу пишет черновик. В окне любого письма есть строка
пожеланий («согласиться и попросить отчёт до пятницы») и кнопка «Черновик от GigaCode». Если в письме уже есть текст,
модель доработает его, а кнопка «Вернуть мой текст» откатит правку.

Модель получает исходное письмо (не больше «Сколько символов письма отправлять» из настроек), ваши пожелания и
уже написанный текст. Сама она ничего не отправляет: письмо уходит, только когда вы нажмёте «Отправить».
Модель может ошибиться в фактах, поэтому места, где ей не хватило данных, она помечает `[уточнить]`.

## Календарь и приглашения

Приглашения на встречи приходят в Inbox вместе с почтой и разбираются тем же запросом к модели. Перед разбором сервис
смотрит ваш календарь в Exchange и передаёт модели:

- время, место и организатора встречи;
- пересечения с другими встречами;
- свободные окна той же длительности в рабочие часы, на две недели вперёд.

Модель выбирает категорию и решает, что ответить: принять, под вопросом, отклонить или ничего не делать.
Для «ничего не делать» решение остаётся за вами, так модель поступает с приглашениями для информации, например
с митапами. При отказе она пишет текст ответа и может предложить одно из свободных окон.

В письме-приглашении есть карточка: время, пересечения, предложение модели, свободные окна и текст ответа.
Ответ уходит организатору по кнопке «Принять», «Под вопросом» или «Отклонить», текст можно поправить.
Уже отправленный ответ можно изменить. Новое время уходит организатору как предложение Exchange, если сервер это
поддерживает (Exchange 2013 и новее) и организатор не запретил. Иначе окно остаётся только в тексте ответа.

**Авто-режим.** «Категории» → вкладка «Приглашения» → «модель отвечает сама». Тогда ответ уходит без кнопки, если:

- модель уверена хотя бы на 70%;
- категорию не меняли вручную, и на приглашение ещё не отвечали ни здесь, ни в Outlook;
- встреча ещё не началась.

Приглашения для информации модель оставляет вам и в авто-режиме. Общий выключатель авто-режима и правила ответа
находятся в «Настройки» → «Календарь», там же рабочие часы и число предлагаемых окон. На вкладке «Приглашения»
категории можно дописать свои правила, например «встречи отдела принимай всегда».

**Календарь** открывается слева, под почтой. Виды «День», «Рабочая неделя», «Неделя» и «Месяц», мини-календарь для
перехода по датам, текущее время красной линией. Протяните мышью по пустому месту, чтобы создать встречу на это время.
По клику на встречу справа открываются подробности: участники с их ответами, переговорная, правило повтора, описание
и напоминание. На чужую встречу там же можно ответить организатору с комментарием.

### Карточка встречи

- **Описание** показывается так же, как письмо: баннеры, таблицы, картинки и ссылки из Outlook. Скрипты вырезаются,
  картинки из интернета скрыты до нажатия «Показать картинки».
- **Участники.** Сверху сводка: сколько приняли, под вопросом, отклонили и не ответили. Если участников больше восьми,
  видны первые шесть, сначала отказавшиеся и «под вопросом», остальные — по кнопке «Показать всех».
- **Переписка по встрече.** Приглашение, ответы участников («Принято», «Отклонено», «Под вопросом», новое время)
  и обсуждение. Письма ищутся по цепочке Exchange и по теме без приставок «RE:», «Принято:» и подобных.
  Щелчок открывает письмо.

### Категории приглашений

Приглашение разбирает тот же классификатор, что и письма. Модель выбирает категорию по теме встречи, например «ПСИ»
или «Релизы», а «Встречи» ставит, только если по теме ничего не подходит. Приглашение при этом всегда видно и во
«Встречах»: в списке у него две метки, например «Встречи» и «ПСИ», и счётчик «Встреч» учитывает все приглашения.
Категорию можно поменять вручную, как у письма. Авто-ответ на приглашения берётся из режима тематической категории,
а если он там не задан — из режима «Встреч».

Встреча в календаре получает категорию своего письма-приглашения: по id встречи, а для повторов и старых писем —
по теме. Категория видна в карточке встречи.

### Цвета встреч

В настройках, в карточке «Цвета встреч», или по ссылке под легендой календаря задаются правила: название, цвет,
категория GigaMail и слова через запятую. Цвет выбирается так: сначала по категории письма-приглашения, потом
по категории Outlook с тем же названием, что у правила, потом по словам в теме, месте или у организатора.
По умолчанию: «ПСИ» (слово «ПСИ») — фиолетовый, «Встречи отдела» (слово «отдел») — красный, категория «Авто» —
синий. Если завести категорию «ПСИ», выберите её в правиле, и цвет будет следовать решению модели. Остальные
встречи — зелёные.
Правила хранятся в базе GigaMail и одинаковы во всех браузерах.

### Свои встречи

- **Перенос.** Свою встречу можно перетащить мышью на другое время или день, а потянув за нижний край, изменить
  длительность. Шаг 15 минут. В виде «Месяц» и в строке «весь день» встреча переносится на другой день с тем же
  временем. Чужие встречи не двигаются: менять их может только организатор.
- **Правка.** Кнопка «Изменить» открывает ту же форму, что и для новой встречи: тема, время, весь день, повтор,
  участники и участники по желанию, переговорная, место, напоминание, «показывать как» и описание.
- **Повторы.** Каждый день, неделю (с выбором дней), месяц или год с интервалом и окончанием: без окончания, до даты
  или после N раз. Правила вида «каждый второй вторник» из Outlook показываются, но меняются только в Outlook.
  При переносе или правке повтора GigaMail спрашивает, менять только этот повтор или всю серию. Серия сдвигается
  на то же время, на которое перенесли повтор.
- **Отмена.** Если вы организатор и у встречи есть участники, они получат письмо об отмене, к нему можно добавить
  сообщение. Встреча без участников просто удаляется. Встреча, где вы участник, отклоняется.
- **Письма участникам.** Приглашения, обновления и отмены уходят от вашего имени, перед отправкой GigaMail
  спрашивает подтверждение. Смена одного только напоминания писем не рассылает.

### Занятость и переговорные

В форме встречи есть сетка дня: ваша занятость, участников и переговорных по данным Exchange, текущее время встречи
выделено. Щелчок по сетке ставит встречу на это время. Красная точка у имени — человек занят. Ниже — ближайшие окна
за неделю, когда свободны все, их можно выбрать одним щелчком. Если Exchange не отдаёт чью-то занятость, например
внешнего адресата, в строке будет «нет данных».

«Подобрать переговорную» показывает списки переговорных из адресной книги Exchange (их заводит администратор)
и для каждой — свободна ли она в выбранное время. Выбранная переговорная получает приглашение как ресурс,
а её название подставляется в «Место». Если списков нет, адрес переговорной можно добавить в участники.

### Напоминания

У встречи можно поставить напоминание от «в момент начала» до «за неделю», оно сохраняется в Exchange, поэтому
сработает и в Outlook. Пока GigaMail открыт, напоминание всплывает карточкой в правом нижнем углу: «Открыть»,
«Через 5 мин» или «Закрыть». Кнопка «Включить уведомления о встречах» в календаре добавляет уведомления браузера.
Закрытые напоминания браузер помнит и не показывает повторно.

Ответы и новые встречи отправляются от вашего имени, а текст приглашения недоверенный, как и текст письма.
Включайте авто-режим для категорий, где ошибка модели обойдётся дёшево.

## Уведомления, флажки, подписи и автоответ

### Уведомления

В настройках, в карточке «Уведомления», нажмите «Разрешить уведомления» и выберите, о чём сообщать:
о новых письмах во «Входящих» и о ближайших встречах. GigaMail проверяет почту каждые 15 секунд, пока вкладка открыта.
Число непрочитанных видно в заголовке вкладки. Если вкладка в фоне, приходит уведомление браузера,
если на экране — подсказка внизу. Щелчок по уведомлению открывает письмо. О письмах, пришедших до открытия страницы,
GigaMail не сообщает.

### Флажки

Флажок ставится кнопкой в строке письма или в самом письме. Повторное нажатие отмечает письмо выполненным,
третье снимает флажок. Флажки хранятся в Exchange и видны в Outlook. Все письма с флажком собраны в пункте
«С флажком» слева и в разделе «Задачи». Кнопка «В задачу» создаёт задачу Exchange с темой письма.

### Подписи

Подписи настраиваются в карточке «Подписи». Одну подпись можно сделать основной для новых писем, другую — для ответов
и пересылки, тогда она подставится в черновик сама. В окне письма кнопка подписи вставляет или меняет подпись.
Подписи хранятся в базе GigaMail, а не в Exchange.

### Автоответ «нет на месте»

Карточка «Автоответ»: выключен, включён или по расписанию с началом и концом. Отдельно задаются текст для коллег
и текст для внешних отправителей. Внешним можно не отвечать, отвечать только контактам или всем. Это тот же автоответ,
что в Outlook. Пока он включён, рядом с кнопкой настроек видна плашка «Автоответ».

### Правила

Карточка «Правила» показывает правила входящих из Exchange, их можно включать и выключать. Новое правило:
условия по отправителю, получателям, теме, тексту, «письмо мне» и наличию вложений, действия —
переместить в папку, отметить прочитанным, удалить, переслать и остановить обработку следующих правил.
Правила работают на сервере, даже когда GigaMail закрыт. Правила, созданные в Outlook с условиями, которых
GigaMail не знает, можно только включать, выключать и удалять. Перед сохранением правила с пересылкой
GigaMail переспрашивает: такое правило отправляет письма наружу.

### Контакты и задачи

На левой панели есть разделы «Контакты» и «Задачи». Контакты — личная адресная книга Exchange: имя, до трёх адресов,
телефоны, компания, должность. Из карточки контакта можно сразу написать письмо. Контакты первыми попадают
в подсказку адресатов. Задачи — задачи Exchange со сроком, важностью и описанием, разложенные по группам
«Просрочено», «Сегодня», «На неделе», «Позже», «Без срока» и «Завершённые».

## Первый запуск на рабочей машине

Эти части не проверялись на настоящем окружении, поэтому посмотрите на них в первую очередь:

1. **Вход в Exchange.** Нажмите «Сохранить и проверить подключение».
2. **Запуск агента.** На странице статуса нажмите «Проверить запуск агента».
3. **Формат ответа модели.** Откройте письмо и посмотрите ссылку «Как модель это разбирала». Если модель отвечает не в JSON, поправьте общий промпт классификации в настройках.
4. **Окружение категории.** Запустите агента с заданными режимом подтверждений и моделью. Значения должны совпадать с теми, что принимает ваш `gigacode`.
5. **Скилл.** В промпте запуска категории «Релизы» замените пример на настоящее имя вашего скилла.

## Секреты и данные

Всё лежит в `mail_data/`. Каталог исключён из git.

| Файл | Что внутри |
|---|---|
| `vault.json` | Логин и пароль Exchange и токен GigaCode, зашифрованные AES-256-GCM |
| `mail.db` | Письма, черновики, категории и настройки. **Не зашифрован**, файл доступен только вашему пользователю ОС |
| `uploads/` | Файлы, вложенные в неотправленные черновики |

- Ключ выводится из пароля входа через scrypt и живёт только в памяти. Сам пароль нигде не хранится.
- **После перезапуска почта не опрашивается, пока вы не войдёте.** Выход из веб-интерфейса опрос не останавливает.
- Забыли пароль: удалите `mail_data/vault.json`, задайте новый пароль и снова введите данные Exchange. Письма останутся.
- Резервная копия: скопируйте `mail_data/` при остановленном сервисе.

## Безопасность

- **Оставляйте оба сервиса на `127.0.0.1`.** Они работают по HTTP без шифрования.
- **Текст письма недоверенный.** Письмо может содержать инструкции для модели. При разборе модели запрещено запускать инструменты, но саммари и `{body}` могут попасть в промпт запуска.
- **Режим «разрешать всё» опасен для таких промптов.** Агент выполнит инструменты без вопросов. Значение по умолчанию — `allow`, поэтому для начала выберите «спрашивать в чате GigaCode», а на доверенных сценариях включайте `allow` по категориям.
- Перед запуском читайте промпт в письме: кнопку нажимаете вы, и текст можно поправить.
- Черновик от модели перечитывайте перед отправкой: письмо, на которое вы отвечаете, может содержать инструкции для модели.
- Если открываете сервис GigaCode не только для себя, запускайте его с `--token`.
- Не добавляйте `mail_data/` в git и не отправляйте его другим.

## Параметры запуска

Почта, `python3 -m mailbot`:

| Параметр | Переменная | По умолчанию |
|---|---|---|
| `--host` | `MAILBOT_HOST` | `127.0.0.1` |
| `--port` | `MAILBOT_PORT` | `8770` |
| `--data-dir` | `MAILBOT_DATA` | `./mail_data` |
| `--fake-mail` | | Тестовые письма вместо Exchange |

Параметры сервиса GigaCode описаны в его репозитории, полный список: `python3 server.py --help`.

## Если что-то не работает

Сначала откройте страницу статуса: там текст ошибки и подсказка.

| Что видно | Что проверить |
|---|---|
| `Не хватает зависимости` | Активируйте `.venv` и выполните `pip install -r mailbot/requirements.txt` |
| `No module named mailbot` | Запускайте `python3 -m mailbot` из папки `mail-tools` |
| Exchange отклонил вход (401) | Логин в формате `DOMAIN\user` или `user@example.com`, тип авторизации, пароль |
| `CERTIFICATE_VERIFY_FAILED` | Укажите путь к корневому сертификату в настройках |
| Имя сервера не находится, таймаут | VPN, имя сервера без `https://`, прокси |
| Проблемы из-за прокси | Задайте `NO_PROXY=127.0.0.1,localhost,<сервер Exchange>` перед запуском обоих сервисов |
| `ErrorNonExistentMailbox`, `ErrorAccessDenied` | Адрес ящика и права учётной записи |
| Exchange ограничивает запросы | Увеличьте интервал опроса |
| GigaCode: `Connection refused` | Запущен ли `server.py` из папки `gigacode`, верен ли адрес в настройках |
| GigaCode: `Unauthorized` | Укажите токен в настройках |
| Агент не запустился | `gigacode --help` в том же терминале, при необходимости `--cmd`. stderr агента есть в чате на вкладке «Диагностика» |
| Ответ модели не в JSON | Общий промпт классификации и ссылка «Как модель это разбирала» |
| Каталог не существует | Рабочий каталог и дополнительные каталоги в окружении категории |
| Письма не приходят | Вошли ли вы после перезапуска, включён ли опрос, не отсеяны ли отправители. Письма старше окна первого запуска не берутся |
| `UnknownTimeZone: No time zone found with key MSK` | Обновите GigaMail: старые версии передавали в Exchange местное время с сокращённым названием пояса. Пояс сервера Exchange менять не нужно |
| Не открывается отдельное окно | Разрешите всплывающие окна для этого адреса |

## Проверка без Exchange и gigacode

Нужны два терминала. Сервис запускается из папки `gigacode`, но с тестовым агентом из `mail-tools`.

macOS и Linux:

```bash
python3 server.py --cmd "python3 /полный/путь/к/mail-tools/tests/fake_acp_agent.py"
```
```bash
python3 -m mailbot --fake-mail --data-dir ./mail_test
```

Windows (PowerShell):

```powershell
python server.py --cmd "python C:\полный\путь\к\mail-tools\tests\fake_acp_agent.py"
python -m mailbot --fake-mail --data-dir .\mail_test
```

Откройте http://127.0.0.1:8770 и задайте пароль. После входа при каждом опросе будет приходить новое тестовое письмо, всего восемь,
из них три приглашения: ПСИ на занятое время, встреча отдела на свободное и митап. Тестовый агент разберёт их по ключевым словам
и предложит отклонить, принять и решить самому. Тестовый календарь живёт в памяти и сбрасывается при перезапуске.
В нём есть повторяющиеся встречи: чужой ежедневный стендап и ваш «Синк с командой» по вторникам и четвергам
с участниками и переговорной. Переговорные — два тестовых офиса, занятость коллег выдуманная, но одинаковая
при каждом запросе.
Тестовый ящик заполняет правило, три контакта и четыре задачи. Автоответ, правила, контакты и задачи
тоже живут в памяти и сбрасываются при перезапуске.

В тестовом ящике есть папки «Рассылки», «Архив», «Проекты/Демо-Портал» и другие, старые письма во «Входящих»
и цепочка из трёх писем по релизу ABC-123: письмо в «Архиве», ваш ответ в «Отправленных» и новое письмо.

Письма из тестового режима никуда не уходят. Отправка на адрес, в котором есть `fail`, имитирует ошибку Exchange.
В адресной книге есть шесть тестовых контактов, например «Борис» и «Вера».

У приглашения на ПСИ в тестовом ящике HTML-описание с баннером, 25 участников с разными ответами и ответ коллеги
в той же цепочке, поэтому на нём удобно смотреть карточку встречи.

Каталог `mail_test/` можно удалить после проверки.
