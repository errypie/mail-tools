# mail-tools

Автоматизация рабочей почты на Exchange с помощью GigaCode CLI.

Сервис забирает письма из Exchange, складывает их в локальную базу и просит модель определить категорию, написать
короткое саммари и решить, нужно ли действие. В веб-интерфейсе вы видите письма с разбором, а агент запускается
только по вашей кнопке. Ход его работы можно смотреть вживую: мысли, инструменты, запросы разрешений.

> Проверено на тестовых письмах и тестовом агенте из `tests/`, а работа с Exchange — на имитации почтового ящика.
> С настоящими сервером Exchange и CLI `gigacode` проект ещё не запускался. На Windows тоже не проверялся.
> Что смотреть при первом запуске, описано в разделе [Первый запуск на рабочей машине](#первый-запуск-на-рабочей-машине).

## Из чего состоит

Это только почта. Агента запускает отдельный сервис из репозитория [gigacode](https://github.com/errypie/gigacode),
поэтому нужны две папки и два процесса на одной машине:

```text
Exchange (EWS) ──> mail-tools :8770 ──> gigacode :8765 ──> gigacode --acp
                   письма, база,        живые сессии агента,
                   веб-интерфейс        веб-чат и HTTP API
```

| Папка | Что внутри |
|---|---|
| `mail-tools/mailbot/` | Опрос Exchange, база писем, категории, шифрование секретов, веб-интерфейс |
| `mail-tools/tests/` | Тестовый агент для проверки почты без настоящего CLI |
| `gigacode/` | Отдельный репозиторий: запускает `gigacode --acp`, отдаёт чат и HTTP API |

## Что нужно

- Python 3.9 или новее.
- Репозиторий [gigacode](https://github.com/errypie/gigacode) рядом с этим.
- CLI `gigacode`, который запускается из терминала и уже авторизован. Проверка: `gigacode --help`.
- Доступ к серверу Exchange по EWS, обычно через VPN или рабочую сеть.
- Адрес сервера Exchange, адрес ящика, логин и пароль.
- Корневой сертификат компании, если сервер использует внутренний удостоверяющий центр.

Сервису gigacode внешние библиотеки не нужны. Почте нужны `exchangelib` и `cryptography`.

## Запуск

Нужны два терминала.

**Терминал 1, сервис GigaCode.** Запускайте из папки `gigacode`. В `--workdir` укажите каталог, где агент будет работать по умолчанию:

```bash
python3 server.py --workdir /путь/к/рабочему/каталогу
```

Если `gigacode` нет в `PATH`, передайте команду явно:

```bash
python3 server.py --workdir /путь/к/каталогу --cmd "node /полный/путь/к/gigacode/dist/cli.js"
```

Откройте http://127.0.0.1:8765. Если чат отвечает, агент работает.

**Терминал 2, почта.** Запускайте из папки `mail-tools` с активным окружением `.venv`:

```bash
python3 -m mailbot
```

Откройте http://127.0.0.1:8770.

## Первая настройка

### 1. Пароль входа

При первом открытии задайте пароль, минимум 8 символов. Им шифруются логин и пароль Exchange.
**Забытый пароль не восстановить.** Что делать в этом случае, описано в разделе [Секреты и данные](#секреты-и-данные).

### 2. Exchange

Откройте «Настройки» → «Exchange»:

| Поле | Что указать |
|---|---|
| Сервер | Только имя, без `https://`: `mail.example.com` |
| Адрес ящика | `name@example.com` |
| Логин | Обычно `DOMAIN\user`. Если вход не проходит, попробуйте `user@example.com` |
| Пароль | Пароль учётной записи |
| Авторизация | `NTLM` для большинства внутренних серверов, иначе `BASIC` |
| Корневой сертификат | Полный путь к файлу `.pem` или `.crt`, если сервер использует внутренний сертификат |
| Интервал опроса | Как часто проверять почту, по умолчанию 15 секунд |
| При первом запуске брать за, дней | Насколько старые письма забрать при первом запуске, по умолчанию 3 |

Нажмите «Сохранить и проверить подключение». Адрес автообнаружения не используется: сервис идёт прямо на
`https://<сервер>/EWS/Exchange.asmx`.

### 3. GigaCode

«Настройки» → «GigaCode»:

| Поле | Что указать |
|---|---|
| Адрес сервиса | `http://127.0.0.1:8765` |
| Токен | Только если сервис запущен с `--token` |
| Рабочий каталог скиллов | Каталог по умолчанию для запуска по кнопке. Пусто — каталог из `--workdir` |
| Разрешения при запуске скилла | Что делать с запросами агента. Сначала лучше выбрать «спрашивать в чате GigaCode», см. раздел [Безопасность](#безопасность) |
| Сколько символов письма отправлять | Ограничение длины письма для модели, по умолчанию 12000 |

### 4. Проверка

Индикаторы Outlook и GigaCode в шапке должны стать зелёными. Клик по индикатору открывает страницу статуса.
На ней кнопка «Проверить запуск агента» поднимает настоящий процесс `gigacode --acp` и закрывает его.

## Категории и промпты

Кнопка «Категории» в шапке открывает отдельную страницу. Сразу есть категории `RELEASE`, `SPAM`, `AUTO`, `UNINFO`
и `UNKNOWN`. Их можно менять, удалять и добавлять свои. У категории есть код (латиница, цифры, `_` и `-`) и название.

### Когда выбирать

Промпт для разбора письма. Модель читает его при разборе каждого письма вместе с промптами других категорий.
На этом шаге она не запускает инструменты и не открывает файлы, поэтому здесь нужны только признаки письма:

```markdown
## Признаки
Письмо про релиз или приёмку задачи.

- В теме или тексте есть Jira-ключ вида ABC-123
- Отправитель из команды релизов

Не путать с автоматическими уведомлениями Jira: их относи к AUTO.
```

Чем длиннее описания всех категорий, тем больше каждый запрос и медленнее разбор.

### Промпт запуска

Текст, который уйдёт агенту по кнопке в письме. Если он пуст, кнопки действия не будет. Здесь пишите скиллы, пути,
код и команды. Перед запуском текст можно поправить прямо в письме.

```markdown
Запусти скилл release-check для задачи {jira_key}.

Сверь изменения с чек-листом и сохрани отчёт в `/data/reports/{jira_key}.md`.

Контекст:
- Тема: {subject}
- Саммари: {summary}

Файлы:
{files}
```

Подставляются переменные:

| Переменная | Значение |
|---|---|
| `{jira_key}` | Jira-ключ из письма |
| `{subject}` | Тема |
| `{sender}` | Адрес отправителя |
| `{summary}` | Саммари модели |
| `{action_hint}` | Совет модели |
| `{body}` | Полный текст письма |
| `{files}` | Список файлов из окружения категории |

Неизвестная переменная подчёркивается красным и уходит агенту как есть.

### Окружение GigaCode

Действует только при запуске по кнопке. Пустое поле берёт значение из настроек или сервиса GigaCode.

| Поле | Что делает |
|---|---|
| Рабочий каталог | Где запускается агент |
| Файлы для агента | Список путей, по одному на строку. Попадает на место `{files}`, а без этой переменной дописывается в конец |
| Дополнительные каталоги | Передаются в `--include-directories`, по одному на строку |
| Режим подтверждений | `plan`, `default` или `auto-edit` |
| Разрешения инструментов | Разрешать всё, спрашивать или отклонять |
| Модель | Идентификатор модели для этой категории |

Каталоги должны существовать на машине, где работает сервис GigaCode. Иначе запуск завершится ошибкой, и она будет видна в письме.

### Проверка на письме

Вкладка показывает оба итоговых промпта и прогоняет разбор на выбранном письме. Берётся текущий текст, даже
несохранённый, а само письмо не меняется.

### Редактор

Markdown с подсветкой кода, путей и переменных, нумерация строк, просмотр рядом, вставка кода и путей.
Клавиши: Ctrl+S сохраняет, Ctrl+B делает текст жирным, Tab и Shift+Tab меняют отступ, Enter продолжает список.

Изменения действуют на новые письма. Чтобы применить их к старым, нажмите «Переразобрать письма»: это один запрос
к модели на письмо. При смене кода категории письма переезжают вместе с ней. Письма удалённой категории остаются
слева с пометкой «удалена».

## Белый и чёрный списки

«Настройки» → «Отправители», по одному адресу или домену на строку: `name@example.com`, `@example.com`.

- Если белый список заполнен, берутся только письма из него. Если пуст, берутся все.
- Чёрный список важнее белого.
- Отсеянные письма не сохраняются и не уходят в модель.
- Кнопки «В чёрный список» и «Заблокировать домен» есть в самом письме.
- Списки действуют на новые письма. Письмо, отсеянное раньше, вернётся после снятия блокировки, только если оно попало в последние 5 минут опроса.

## Работа с письмами

1. Сервис забирает новые письма из Inbox. Признак «прочитано» не используется и не меняется, дубли отсекаются по `Message-ID`.
2. Один запрос к модели возвращает категорию, уверенность, саммари, Jira-ключ и рекомендацию.
3. При сбое или ответе не в JSON будет 5 попыток с растущей паузой, затем статус «Ошибка» и кнопка «Классифицировать заново».
4. Если GigaCode недоступен, попытки не тратятся: письма ждут в очереди и разбираются после восстановления.
5. Кнопка в письме создаёт живую сессию. Ссылка «Открыть в GigaCode» показывает мысли и инструменты агента.

Интерфейс:

- Границы между папками, списком и письмом тянутся мышью. Двойной клик по границе сбрасывает ширину.
- Кнопка «↗ В отдельном окне» открывает письмо без списка: текст слева, разбор и запуск агента справа.
- Страница статуса показывает последний опрос, очередь, текст ошибок и подсказки, что проверить.

## Первый запуск на рабочей машине

Эти части не проверялись на настоящем окружении, поэтому посмотрите на них в первую очередь:

1. **Вход в Exchange.** Нажмите «Сохранить и проверить подключение».
2. **Запуск агента.** На странице статуса нажмите «Проверить запуск агента».
3. **Формат ответа модели.** Откройте письмо и посмотрите ссылку «Как модель это разбирала». Если модель отвечает не в JSON, поправьте общий промпт классификации в настройках.
4. **Окружение категории.** Запустите агента с заданными режимом подтверждений и моделью. Значения должны совпадать с теми, что принимает ваш `gigacode`.
5. **Скилл.** В промпте запуска категории «Релизы» замените пример на настоящее имя вашего скилла.

## Секреты и данные

Всё лежит в `mail_data/`. Каталог исключён из git.

| Файл | Что внутри |
|---|---|
| `vault.json` | Логин и пароль Exchange и токен GigaCode, зашифрованные AES-256-GCM |
| `mail.db` | Письма, категории и настройки. **Не зашифрован**, файл доступен только вашему пользователю ОС |

- Ключ выводится из пароля входа через scrypt и живёт только в памяти. Сам пароль нигде не хранится.
- **После перезапуска почта не опрашивается, пока вы не войдёте.** Выход из веб-интерфейса опрос не останавливает.
- Забыли пароль: удалите `mail_data/vault.json`, задайте новый пароль и снова введите данные Exchange. Письма останутся.
- Резервная копия: скопируйте `mail_data/` при остановленном сервисе.

## Безопасность

- **Оставляйте оба сервиса на `127.0.0.1`.** Они работают по HTTP без шифрования.
- **Текст письма недоверенный.** Письмо может содержать инструкции для модели. При разборе модели запрещено запускать инструменты, но саммари и `{body}` могут попасть в промпт запуска.
- **Режим «разрешать всё» опасен для таких промптов.** Агент выполнит инструменты без вопросов. Значение по умолчанию — `allow`, поэтому для начала выберите «спрашивать в чате GigaCode», а на доверенных сценариях включайте `allow` по категориям.
- Перед запуском читайте промпт в письме: кнопку нажимаете вы, и текст можно поправить.
- Если открываете сервис GigaCode не только для себя, запускайте его с `--token`.
- Не добавляйте `mail_data/` в git и не отправляйте его другим.

## Параметры запуска

Почта, `python3 -m mailbot`:

| Параметр | Переменная | По умолчанию |
|---|---|---|
| `--host` | `MAILBOT_HOST` | `127.0.0.1` |
| `--port` | `MAILBOT_PORT` | `8770` |
| `--data-dir` | `MAILBOT_DATA` | `./mail_data` |
| `--fake-mail` | | Тестовые письма вместо Exchange |

Параметры сервиса GigaCode описаны в его репозитории, полный список: `python3 server.py --help`.

## Если что-то не работает

Сначала откройте страницу статуса: там текст ошибки и подсказка.

| Что видно | Что проверить |
|---|---|
| `Не хватает зависимости` | Активируйте `.venv` и выполните `pip install -r mailbot/requirements.txt` |
| `No module named mailbot` | Запускайте `python3 -m mailbot` из папки `mail-tools` |
| Exchange отклонил вход (401) | Логин в формате `DOMAIN\user` или `user@example.com`, тип авторизации, пароль |
| `CERTIFICATE_VERIFY_FAILED` | Укажите путь к корневому сертификату в настройках |
| Имя сервера не находится, таймаут | VPN, имя сервера без `https://`, прокси |
| Проблемы из-за прокси | Задайте `NO_PROXY=127.0.0.1,localhost,<сервер Exchange>` перед запуском обоих сервисов |
| `ErrorNonExistentMailbox`, `ErrorAccessDenied` | Адрес ящика и права учётной записи |
| Exchange ограничивает запросы | Увеличьте интервал опроса |
| GigaCode: `Connection refused` | Запущен ли `server.py` из папки `gigacode`, верен ли адрес в настройках |
| GigaCode: `Unauthorized` | Укажите токен в настройках |
| Агент не запустился | `gigacode --help` в том же терминале, при необходимости `--cmd`. stderr агента есть в чате на вкладке «Диагностика» |
| Ответ модели не в JSON | Общий промпт классификации и ссылка «Как модель это разбирала» |
| Каталог не существует | Рабочий каталог и дополнительные каталоги в окружении категории |
| Письма не приходят | Вошли ли вы после перезапуска, включён ли опрос, не отсеяны ли отправители. Письма старше окна первого запуска не берутся |
| Не открывается отдельное окно | Разрешите всплывающие окна для этого адреса |

## Проверка без Exchange и gigacode

Нужны два терминала. Сервис запускается из папки `gigacode`, но с тестовым агентом из `mail-tools`.

macOS и Linux:

```bash
python3 server.py --cmd "python3 /полный/путь/к/mail-tools/tests/fake_acp_agent.py"
```
```bash
python3 -m mailbot --fake-mail --data-dir ./mail_test
```

Windows (PowerShell):

```powershell
python server.py --cmd "python C:\полный\путь\к\mail-tools\tests\fake_acp_agent.py"
python -m mailbot --fake-mail --data-dir .\mail_test
```

Откройте http://127.0.0.1:8770 и задайте пароль. После входа при каждом опросе будет приходить новое тестовое письмо, всего четыре.
Тестовый агент разберёт их по ключевым словам.

Каталог `mail_test/` можно удалить после проверки.
